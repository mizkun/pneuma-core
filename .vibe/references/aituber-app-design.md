## 1. プロジェクトの北極星（アプリ層）

**「AI 自律的行動から生まれるエンタメ」を AITuber 形式で世間に出す。**

Pneuma 全体の North Star（`vision.md`）= 「AI キャラたちが暮らす世界そのものを IP として育てる」を、第一弾アプリケーションとして実装する。AITuber は North Star を実現する **形式の一つ**。

## 2. プロダクト・コンセプト

### 2.1 形式：女子高生 3 人の部活 AITuber

- **3 キャラクター**（女子高生・放送部所属）が、部室で雑談する
- **配信フォーマット**：定点カメラ視点（部室を覗き見しているような構図）
- 視聴者は「3 人の AI が勝手に活動しているのを覗き見ている」感覚を得る
- ゆゆ式 / まんがタイムきらら的な世界観

### 2.2 ビジュアル（紙芝居方式）

- **背景固定**：部室の生成 AI イラスト 1 枚（または時間帯 / シチュ別に数枚）
- **キャラクター立ち絵レイヤー**：各キャラごとに複数パターン
  - 感情パターン（喜・怒・哀・楽・驚・通常 など最低 6〜8 種）
  - ポーズパターン（座ってる / 立ってる / 身振り中 など）
  - PAD / emotion_label → 立ち絵切り替えの直結マッピング
- Live2D は使わない（一旦）。静的画像差し替えのみ
- 移動・位置の概念は持たない（定点カメラ + 紙芝居）
- 発話中のキャラ表示 UI（リップシンクなし、発話者マーカー）
- 画像素材は ChatGPT 等で PO が別途用意（AI 主導の開発スコープ外）

### 2.3 音声（MUST）

各キャラに異なる音声合成キャラを割り当てる。

**採用（2026-05-27 ADR-0001 で確定）: ElevenLabs Multilingual/v3**
- 多言語対応・感情演技の幅・低レイテンシ（Flash 75ms / Turbo 250〜300ms）
- 8 時間/日運用で月約 2 万円、Phase 1 (15 分/日) で月約 $13.50
- ストリーミング対応、声ライブラリが豊富で 3 体識別性を作りやすい
- Phase 0 D の PoC で Aivis と横並び実測。日本語キャラ性で大差なければ確定、極端に弱ければ Aivis に戻す

**不採用: Aivis Cloud API**
- 日本語キャラ声らしさは強いが、プレミアム 1,980 円/月は 10 req/min レート制限で 3 体ストリーミングに合わない
- 従量プランは 8 時間/日で月 19 万円と高い
- Phase 0 D の PoC で逆転があれば再採用検討

詳細は `.vibe/references/tts-research-2026-05-27.md` と `.vibe/decisions/0001-architecture.md` 参照。

**採用条件（全候補共通）：**
- 使う 3 声のライセンスを商用 YouTube Live・収益化・アーカイブ・切り抜き・SNS 転載・将来の IP 展開まで含めて厳密に確認
- 既存声優・VTuber・配信者に似た声は採用しない（にじボイス終了の教訓）
- 本人同意のない voice cloning は行わない

**運用設計上の制約：**
- **感情ラベルは `neutral / happy / teasing / surprised / embarrassed / sad-lite` の 6 種に限定**。`angry` は基本使わない（女子高生雑談での過剰演技回避）
- **発話は 1〜2 文単位で TTS に流す**（長文 1 発投げは禁止）。低レイテンシ達成のため
- **3 声の識別は声質だけでなく、話速・語尾・口癖・字幕色・立ち絵で複合的に差別化**
  - キャラ A: 明るく早口、少し高め
  - キャラ B: 落ち着き、やや低め、間が長い
  - キャラ C: ツッコミ役、中速、語尾が鋭い
- **OpenAI を採用した場合は AI 音声であることの開示が必要**（番組概要・固定コメント・テロップ等）
- 「えっと」「なるほどね」などの定型相づち音声はキャッシュ化を検討

**PoC 計画（Phase 1 着手時）：**
- 同一台本（通常会話 / ツッコミ / 照れ / 長めの説明 / 固有名詞）で Top 3 候補を横並び実測
- 測定値: first audio byte / 再生開始 / 全文生成完了 / イントネーション / 固有名詞読み / 識別性 / OBS 経由の聞き取りやすさ

### 2.4 番組設定

- 部活内輪トーク垂れ流しスタイル
- 視聴者からの介入なし（YouTube は完全観察専用）
- PO 介入は **セッション開始時のコンテクスト注入のみ**

## 3. 上位存在の介入仕様

Pneuma の世界観として、**上位存在は環境のみに介入し、キャラの内面には直接干渉しない**。キャラは環境変化を観察して反応する。

### 3.1 介入手段

- **セッション開始時のコンテクスト注入**：自由テキストで「今日は文化祭の準備中」「雨が降っている」「アイネが新しい本を持ってきた」等を渡せる
- 会話途中での動的環境介入は **やらない**（Phase 1 では）
- キャラの内部状態（PAD / 記憶）への直接書き換えは **やらない**
- 「天啓」「夢で誘導」のような直接干渉も **やらない**

### 3.2 介入できるのは PO のみ

- 一般視聴者は介入できない
- 介入のためのインターフェースは管理者向けの UI（実装方式は Issue 分解時）

## 4. 発話・行動モデル

### 4.1 ターンモデル

- 3 体は順番にターンが回る（A → B → C → A → ...）
- 各ターンで「思考」が必ず走る（LLM 推論 1 回）
- 思考の出力は **(行動, 発言)** のペア
  - 発言：話す内容（空 = 何も言わない / 沈黙）
  - 行動：物理的な動き（話しかける、笑う、はにかむ、下を向く等）
    - ※ Phase 1 では "部屋を出る" 等の場所変更を伴う行動は実装しない（位置概念なし）
- 発言と行動は **毎ターン同時に出る**（例：はにかみながら話す）

### 4.2 既存資産との対応

pneuma-core の `RuntimeEngine` には既に `speech / thought / action` の structured response がある。これをそのまま 3 人版に拡張する。

### 4.3 ターン頻度

- Phase 1 では 1 セッション = 15 分（長さは試運用で調整）
- ターン間隔（1 ターンあたりの実時間）は試運用で決定
- 会話中は頻度高め、非会話時は低め、というロジックは Issue 分解時に詰める

## 5. 出力アーキテクチャ（3 層）

### 5.1 表：ライブ配信（エンタメ層）

- **Web サイト自動配信**：誰でも視聴可、毎日自動でセッションが動く。配信時間外は「次回配信時刻」が表示される待機画面
- **YouTube Live 配信**：Web サイトの映像を OBS 経由でキャプチャ → YouTube Live に流す。**PO が手動で**（流したい時だけ）

### 5.2 裏：観察ダッシュボード（深掘り層）

Web サイト上で、誰でも見られる。

**Phase 1 スコープ：**
- 3 キャラぶんの Big Five（静的）
- 3 キャラぶんの PAD（現在の感情）
- 関係性スコア（現在）
- 直近の会話ログ
- 想起された記憶のハイライト
- 各キャラの最新日記

**Phase 2 以降：**
- 過去の感情推移グラフ
- 日記一覧
- 全記憶リスト
- 検索機能等

### 5.3 思想：note 記事（解説層）

- Pneuma の仕組み解説（Big Five × PAD × 記憶バイアス RAG）
- 「パーソナリティ心理学を AI に持ち込んだ第一人者」のポジ取り
- 観察記録の note 化（"今週のあの掛け合いの裏側" 的）
- **PO 個人タスク扱い**（AI 主導の開発スコープ外）

## 6. 競合との差別化

### vs AUTOMATA（佐藤航陽さん）
- AUTOMATA：大量エージェント × 生態系スケール × 横方向（広さ）
- **Pneuma：個々のキャラの人格深度 × 関係性の物語発芽 × 縦方向（深さ）**

### vs 既存 AITuber（Neuro-sama 等）
- 既存：一人芸が主流、演出されたカメラワーク
- **Pneuma：定点カメラの覗き見、3 人掛け合い、人格深度に基づく自然な性格差**

ワンライナー候補：
- 「のぞき見できる AI 放送部」
- 「群じゃなく個性で勝負する AI 箱庭」
- 「AUTOMATA が世界を作るなら、Pneuma は登場人物を作る」

## 7. キャラクター設計の方針

3 人とも女子高生・放送部所属。Big Five パラメータで明確に対比させる。

例（あくまで例、要設計）：
- **キャラ A**：外向性高、楽天的、突っ込み役
- **キャラ B**：内向性高、好奇心強、観察役
- **キャラ C**：神経質、共感性高、情緒役

各キャラの YAML（pneuma-core の `character.yaml` 形式）で性格パラメータ・口調・プロファイルを定義。

**キャラ設定は PO が別セッションで詰める。** 設定が来てから立ち絵生成や character.yaml 整備が並走できる。

### 技術スタック（ADR-0001）

| レイヤー | 採用 |
|---|---|
| Web ホスティング + 認証 + 永続化 + 画像 | **Firebase Hosting / Auth / Firestore / Storage** |
| バックエンド（Python） | **Cloud Run + FastAPI** |
| ダッシュボードのリアルタイム同期 | **Firestore `onSnapshot`**（自前 WebSocket 不要） |

| 監視 | **Cloud Logging + Sentry** |
| 配信 | OBS で Web キャプチャ → YouTube Live（手動） |

## 9. 第 1 弾 MVP スコープ（Phase 1）

### 必須要素
- pneuma-core を依存として、3 キャラ会話エンジン（既存 cross_chat の拡張）
- キャラ 3 人の `character.yaml`（性格・プロファイル・立ち絵参照・音声 ID）
- 各キャラの立ち絵セット（最低 感情 × 3 キャラ = 18〜24 パターン）— **PO が用意**
- 背景画像 1 枚（放送部の部室）— **PO が用意**
- TTS パイプライン（選定は別 Research タスク）
- Web サイト UI（背景 + 立ち絵レイヤー + 発話者マーカー）
- セッション制御（自動で 15 分動く、Web サイトに公開）
- ダッシュボード（Section 5.2 の Phase 1 スコープ）
- PO 管理者 UI（コンテクスト注入用）
- OBS で Web サイトをキャプチャ → YouTube Live は手動運用（手順書のみ用意）

### スコープ外
- キャラ SNS 能動発信（M2 へ）
- 真の 24/7 連続稼働（M3 へ）
- ダッシュボード過去履歴系（Phase 2 へ）
- 切り抜き自動生成（M2 へ、Phase 1 は手動）
- note 記事、X 運用、立ち絵生成、背景生成（PO 個人タスク）

## 11. 視聴者・差別化に関する設計指針（戦略レビュー指摘の吸収）

### 11.1 最初の 100 人のターゲット仮置き

「AI / プロダクト系で SNS 発信が活発な技術者・クリエイター層」を最初の 100 人として仮置きする。
- Vtuber ファン / きらら系ファンは "後から取りに行く" 扱い
- ターゲット 1 つに絞ることで note 解説記事・配信トーン・キャラ設定の方向性が一貫する

### 11.2 ライブ画面に「内面の滲み出し」演出

ダッシュボードを別タブに置くだけだと、視聴者は開かないし差別化が伝わらない。**Web フロントのライブ画面そのものに以下を組み込む：**
- PAD ゲージのオーバーレイ（キャラの近くに小さく表示）
- 関係性スコアの変化を矢印アニメで一瞬表示
- 想起記憶のフラッシュテロップ（「いま思い出してる：◯◯」）

これがあって初めて、ライブ視聴者にもパーソナリティ心理学アルゴリズムが体感として届く。

### 11.3 MVP 検証ゲート（Phase 0 C2）

人間が台本を書くのは Pneuma の North Star（AI 自律会話）に反する。代わりに **AI を実際に走らせてテキスト出力を観る** ことで「観たいか」を検証する：
- C で multi-agent + キャラ 3 人設定を実装
- C2 でテキストのみで 3 体を走らせ、PO が観て「面白い／面白くない」を判定
- 「面白くない」なら C に戻る（プロンプト・キャラ・FloorController を調整）
- 「面白い」なら D 以降（TTS / UI / 立ち絵 / 配信）に進む

## 12. Iris への引き継ぎ要約

- 本アプリケーションは pneuma-core を **AITuber 配信プラットフォーム**として活用する
- 3 キャラ女子高生・放送部・定点カメラの覗き見スタイル
- 出力は **ライブ + 観察ダッシュボード + note 記事** の 3 層
- 技術スタックは Firebase + Cloud Run + ElevenLabs（ADR-0001 で確定）
- **Phase 0 = 着手前の前提固め（multi_agent 新規設計、テキスト試聴ゲート、TTS PoC、emotion_label 単一化、コスト hard limit、Moderation）**
- **Phase 1 = MVP 公開**（Phase 0 完了後に Issue 群起票）
- 次のアクション：(1) Phase 0 Issue を起票（C / C2 / D / E / F / G）、(2) PO 並列タスクでキャラ 3 人設計
