## 0. 一行で

**上位存在が、ルール制約の下で介入し、"ゴール" を目指し、巻き戻し・分岐で試行錯誤しながら、AI の創発を観察する。その全過程が「実験記録」としてエンタメになる。**

「観察対象であること自体がエンタメ」——介入したら何が起きるか？ が謎になり、本物の創発が解明になる。台本で答えを決められない（決めたら実験ではない）から、台本化を 100% 回避しつつ謎と解明のエンタメが成立する。

## 1. ここに至るまでの試行錯誤（記録）

このコンセプトは一発で出たものではなく、Phase 0 の実機検証と壁打ちの積み重ねで到達した。経緯を残す。

### 1.1 出発点

- M1 を AITuber プラットフォーム MVP として定義（3 体女子高生・部室・定点カメラ）。詳細は `.vibe/references/aituber-app-design.md`。
- 思惑エンジン（#20）まで実装し、リアル Claude で 3 体会話を実機検証できる状態にした。

### 1.2 試聴ゲートでの気づき（面白さの壁）

リアル Claude で走らせた結果、PO 判定は一貫して「それっぽいが、すごく面白くはない／落ちがない／日常アニメってこのくらい」。ここから「面白さとは何か」を掘った。

到達した理論（詳細は `fun-engine-design.md`）:
- **面白さ = 共感（解釈一致）と発見の共存。**
- **面白さ = 謎 → 解明の繰り返し。** 謎度はコンテクスト依存（愛着＝ハイコンテクスト）。
- ラジオのお便り = ローコンテクストな謎の供給装置。
- 台本化しない = 展開を書かず「火種＋着火条件」を仕込む。
- 視聴者非意識のまま会話を駆動するために「思惑（短期ゴール）」を使う。

### 1.3 面白さエンジン（#22）の実装と限界

クセ・テンポ・水平思考・感情ダイナミクス・構造的オチをトグル可能に実装し、全 ON で実機検証。フル機能版で初めて「起承転結＋引きのあるオチ」が成立した（フグ→恋愛→運→締め）。

しかしエンタメ専門家パネル（構成作家・放送作家・キャラ脚本家・エンタメ P）による解析の結果（平均 4.5/10）、4 視点全員が同じ致命傷を指摘:
1. 対立ゼロ・全員 happy 固定（引きがない）
2. 本音が反復・不変で伏線にならない
3. PAD とテキストの乖離（観測の信頼性＝計器の問題）

そして「皮肉にも機能の少ない版の方がドラマがあった。フル機能化が角を丸めてフックを殺した」。

### 1.4 PO の違和感 → 路線の発見

PO の違和感:
- 「裏の思惑が見える前提のエンタメは違う。表の発言・会話だけで面白くあるべき。thought に頼ってはいけない」
- 「面白いことを起こそうという方向＝既存エンタメ手法を自発的に起きてるように見せる方向に寄っていて、台本に近い、テレビ番組的、思ってたのと違う」

ここで 2 つの路線が衝突していることが判明:

| | 路線A: エンタメ IP | 路線B: 観察・実験 |
|---|---|---|
| 目的 | 観客を楽しませる作品 | 上位存在として創発を観る |
| 面白さの源 | 作られた面白さ（演出・芸） | 本物が動いてる面白さ（予測不能） |
| 系譜 | Neuro-sama / 日常アニメ | Generative Agents / AI Town |
| 競合 | プロの芸（赤い海） | ほぼ無人（青い海） |

専門家パネルは路線A 前提の助言だった。だが PO の元 Vision（上位存在として箱庭を眺める）は路線B。エンタメ手法に寄せたのが回り道だった。

### 1.5 統合の発見

PO の決定打:
> **「観察対象であることがエンタメであるべき。そうすると、この介入をしたら何が起きるのか？ 自体が謎になるから、観察記録・実験記録みたいなコンテンツとして出せる」**

さらに 2 つのアイデアでコンセプトが完成:
- **巻き戻し・分岐**（git のように世界線を操作 → 反復観察・複数試行が可能に。LLM は非決定的〔seed なし〕なので決定論的な統制実験ではなく、同一介入を複数試行して傾向で比較する）
- **ゴール + ルール**（例: AI に AI だと気づかせる / 直接伝えてはいけない → パズル化）

これにより路線A と B が統合された。観察（B）が、介入実験の謎と解明を通じてエンタメ（A）になる。

## 2. コンセプトの構造

### 2.1 4 つの役割

- **上位存在（PO / 将来は視聴者も）**: ルール制約下で介入する神プレイヤー。ゴール達成を目指す。
- **AI キャラ（被観察者）**: 性格・感情・記憶・関係性・思惑を持ち、自律的に振る舞う。視聴者を意識しない（下位存在）。
- **観客（視聴者）**: 「介入したらどうなるか」の謎を上位存在と共有し、結果を観る。神の試行錯誤を観戦する。
- **計器（観測系）**: thought・PAD・記憶・関係性をデータとして可視化。芸ではなく実験の証拠。

### 2.2 なぜ強いか

- **謎**: ゴール達成できるか？ どう介入すれば？（大謎）／各介入で何が起きる？（小謎・高頻度）
- **パズル**: 「直接伝えてはいけない」等の制約が工夫を生む（制約こそゲームデザインの核）
- **創発の純度**: AI が「自力で気づいた」感が出る（押し付けでない）
- **リプレイ性**: 分岐で「もしこう介入したら」を何度も試せる
- **本物**: 結果を台本で決められない（＝台本化の完全回避）
- **両輪との一致**: 実験記録はエンタメであり、同時にパーソナリティ心理学アルゴリズムの実証（技術発信）

### 2.3 thought（内心観測）の正しい位置づけ

thought は「内心を見せる芸（飛び道具）」ではなく **「実験の観測データ」**。主役は表の振る舞い（発言・行動・関係変化）の創発。thought はその観察を深める窓。これで PO の「thought に頼るな、表で勝負」が満たされる。

## 3. 運用イメージ

### 3.1 配信サイクル（定期 15 分 YouTube 想定）

```
[予告]  X / YouTube「次の実験: ゴール◯◯に、ルール△△で挑む。どうなる?」← 謎を提示
   ↓
[配信]  15 分ライブ。上位存在が介入(commit)→ AI が創発で反応。
        失敗したら巻き戻し(checkout) / 別手を試す(branch) = 神の試行錯誤自体が見せ場
   ↓
[結果]  ゴール達成 or 失敗 → カタルシス or 次回へ
   ↓
[記録]  アーカイブ + 実験レポート(note) + 切り抜き + 世界線ツリー(観測サイト)
```

### 3.2 git 比喩（世界線管理）

| git | Pneuma |
|---|---|
| commit | 状態スナップショット（介入や各ターン後） |
| branch | 世界線の分岐（「もしこう介入したら」） |
| checkout | 巻き戻し |
| log / graph | 実験履歴（世界線ツリー） |
| diff | 介入前後の内部状態の変化 |

### 3.3 コンテンツ単位

「15 分ライブ」ではなく **「1 実験 = ゴール + ルール + 起点状態 + 介入列 + 結果」** が 1 エピソード。これが note 記事・切り抜き・アーカイブの単位になる。

### 3.4 配信モード（未決定の論点）

- ガチ一発勝負（巻き戻しなし、創発の純度・緊張感が最大、外す可能性あり）
- 試行錯誤を見せる（巻き戻し・分岐を演出として使う、神の試行錯誤がコンテンツ、視聴者が「次どの世界線へ?」参加）
- 両方をモードとして用意する案もある

## 4. ルール / ゴールのカタログ（具体例）

### ゴール（実験のお題＝謎）

| 難度 | ゴール例 |
|---|---|
| 軽 | 2 人を喧嘩させて仲直りまで導く / 全員を特定の話題に自発到達させる |
| 中 | 秘密を全員に共有させる / 1 人に「部室を出る」決断をさせる / 2 人を相思相愛にする |
| 重 | AI に「自分が AI だ」と気づかせる（自己認識実験） |

### ルール（介入の制約＝パズル化）

- 直接命令・直接告知してはいけない（間接介入のみ）
- 1 配信で介入は N 回まで（リソース制約）
- 環境・刺激のみ、内面に直接触れない（元の世界観）
- 嘘をついてよい / いけない

制約があるほどパズルになり、達成時の「自力で気づいた感」が出る。

## 6. 技術コア：状態の完全シリアライズ

巻き戻し / 分岐 / 履歴は全て **「状態を完全に保存・復元できる」** ことに帰着する。そして既に `MultiAgentSession.snapshot()` がある（今は観測用に状態を dict 化しているだけ）。これを「復元可能な完全スナップショット」に育てれば:

- `snapshot()` → commit
- `restore(snap)`（新規）→ checkout
- snapshot から別系統で再開（新規）→ branch
- スナップショットの木構造（新規）→ 履歴 DAG

ADR-0001 で計画していた Firestore 永続化が、ここで「実験基盤」として本来の意味を持つ。既存資産が活きる設計。

## 9. North Star との関係

この「神の実験室」コンセプトは Vision を否定しない。むしろ Vision の North Star「AI キャラたちが暮らす世界そのものを IP として育てる／上位存在として観察する」の最も尖った具体化である。AITuber 配信は North Star の "出口の一つ" であり、コアは「上位存在が介入実験し、創発を観察・記録する」こと。
